# dsh-butler-install

大管家全家桶的**薄壳安装器**：一条命令按清单装齐插件与命令行工具，装完**立刻告诉你成了没**，红了能整批回滚。

> 卖点不是"一键"，是"一键之后的可验证性"。
> 一个包"装完 rc=0 但其实没生效"是这套生态里真实存在过的坑（宿主只会吐一行
> `declares no dsh.bundle` 警告，然后把它装成普通依赖）。本工具逐包核对**包实体在不在、
> 版本落不落在期望区间、插件到底有没有进组合列表**，任一条不过就判这一步失败。

## 30 秒上手

```powershell
# ① 先看它会做什么（默认就是演练档：一条命令都不跑，零写入）
npx @kira905/dsh-butler-install --profile web

# ② 真装
npx @kira905/dsh-butler-install --profile web --apply

# ③ 只装一部分（组名 / 包名 / 别名都认）
npx @kira905/dsh-butler-install --profile web --apply --only 面板,看板
```

装完/以后任何时候的自检，是 `dsh-butler-core` 仓里那条装后自检：

```powershell
node <dsh-butler-core 仓根>/selfcheck-replica.mjs --manifest suite-manifest.json
```

> ⚠️ **这条自检命令的现状**：它目前在 `dsh-butler-core` 仓里，**还没有接清单**
> （只跑它内置的那几项判据）。本仓的 `suite-manifest.json` 的字段是**为它将来接清单准备的**
> —— 字段含义见下文「清单字段」一节。别把它当成"已经能按清单跑了"。

## 想要个界面？`--ui`：挂在 DSH 外面的只读向导页

觉得命令行清单不好对？加 `--ui` 起一个本地网页，每一行写清**装没装 / 什么版本 / 期望区间**，
按钮只帮你**复制命令**：

```powershell
# 起向导页（不会装任何东西、不会重启你的 DSH）
npx @kira905/dsh-butler-install --ui

# 换端口（默认 45080；被占会自动往后挑一个并打印实际地址）
npx @kira905/dsh-butler-install --ui --port 45090
```

打开它打印的地址（形如 `http://127.0.0.1:45080/`）就能看到清单表。页面上只有两个动作：

| 按钮 | 干什么 | 不干什么 |
|---|---|---|
| **复制命令** | 把这件要跑的**那一行**放进剪贴板 —— 与 `--dry-run` 打印的是**同一行**（同一个函数产出） | 不替你执行；你仍然要在终端里自己跑 |
| **重查** | 重跑一遍探测、把最新读数写回同一张表 | 不改任何状态、不安装、不写文件 |

### 为什么挂在 DSH 外面，而不是做成插件侧边栏页

这是设计前提，不是偷懒：

| | 插件侧边栏页（最初的想法） | 宿主外的本地页面（现在这样） |
|---|---|---|
| 要装插件 / 重启 DSH | 要（`dsh.bundle` + `cordis.patch.yml` + 重启） | **不要** |
| DSH 升级会不会崩 | 会（往页面里注入 client DOM，宿主一改就可能失效） | **不会**（它根本不进宿主） |
| 装 DSH 之前能不能用 | 不能 | **能** —— 还没装宿主时，向导正好可以告诉你"你得先装 DSH" |
| 成本 | 约 8h | **约 4h** |
| 代价 | 写入口的风险面大 | 要监听一个本地端口（所以**只许 `127.0.0.1`**） |

### 安全边界（写死的，不是可选项）

- 🔴 **只绑 `127.0.0.1`**：同一局域网的别的机器连不上。没有 `0.0.0.0` 开关，也不读环境变量改它。
- 🔴 **只有两个 `GET`**：`GET /`（页面）与 `GET /state`（与 `--dry-run` 同源的 JSON）。
  任何 `POST` / `PUT` / `DELETE` / `PATCH` / `OPTIONS` / `HEAD` 一律 **405** + `Allow: GET`，其余路径 404。
- 🔴 **服务端一条命令都不执行**：没有写入口，页面也不会替你跑 `dsh` / `npm`。
  启动时只做一次只读的 `npm config get prefix` 来定位全局包落点，之后**每个请求零 spawn**。
- 端口被占：自动往后挑一个（最多 20 个），都不行就让系统分配，并**打印实际地址**。

### 「按顺序装」是什么意思

页面会给你**建议顺序 + 为什么这么建议**，但请看清它的含义：

> **组件之间没有代码依赖，谁先装谁后装都能装上。** 真正有先后的只有三格：
> Node（≥22）→ `dsh` 主包 → profile。下面的"顺序"是**给人看的排查路径**，不是成功的前提。
> 看到"必须按 1→2→3 才能成功"这种话，那是假的仪式。


## 它只做两件事，且只用两个原语

| 原语 | 用来装什么 |
|---|---|
| `dsh plugin --profile <p> add <包>@<期望区间>` / `remove <包>` | 插件类（要进 profile 的组合列表） |
| `npm i -g <包>@<期望区间>` / `npm rm -g <包>` | 命令行类（不参与挂载） |

明确**不做**（这是设计红线，不是懒）：

- **不写** `dsh.profile.bundles` —— 那是宿主的活；本工具只调 `dsh plugin add`，让宿主自己登记。
- **不写** `cordis.patch.yml` —— 需要手工 insert 的包，本工具只告诉你"它要手工挂"，不代劳。
- **不碰** `node_modules` —— 不自己下载、不解包、不建链接。代码里没有第二条装包路径。
- **不重启**你的 DSH，不改别的仓，不帮你决定要不要装。

删掉本工具，一切照旧：它没有留下任何自己的运行时状态（只有回滚快照，见下）。

## 为什么安装命令要带 `<包>@<期望区间>`

因为注册表的 `latest` 标签和"最高版本号"不是一回事。实测踩过：某个包的 `latest`
指着一个旧版本，而更新的版本确实已发布、却没被 `latest` 指着 —— 不带区间装上来的是
**旧的那一版**，于是"期望 ^0.1.1、实体 0.1.0"，装完看着成功、实际装错了版本。

带上区间之后，解析器只能落在期望区间里：落不进去就报错停下（而不是装个别的版本还报成功）。

## 退出码

| 码 | 含义 |
|---|---|
| `0` | 全绿（含"本来就已满足、这次全跳过"） |
| `2` | 用法 / 清单 / 前置条件错误 —— **什么都没改** |
| `3` | 有步骤失败，但**已回滚干净** |
| `4` | 有步骤失败，且**回滚不干净**（要人看：报告里会指出哪份文件对不上、快照在哪） |

## 回滚：两级，别只做一级

失败时默认**只退失败那一步**（前面已装好的几步保留，不用全重来）：

| 参数 | 干什么 |
|---|---|
| `--rollback` / `--rollback=step`（默认） | 回到**失败那一步之前**：先卸掉这一步装进去的包，再回放那一步之前拍的快照 |
| `--rollback=batch` | 回到**本轮开跑之前**：逐包卸掉本轮装过的，再回放开跑前的快照 |
| `--uninstall` | **不是回滚**：把选中的包从 profile / 全局前缀卸掉（"我不想装这套了"） |

一句话分清：**回滚看的是"这一轮做了什么"，卸载看的是"现在装着什么"。**

快照拍的是**声明层文件**：`package.json`、`pnpm-lock.yaml`、`cordis.patch.yml`，
外加包管理器自己会写的 `pnpm-workspace.yaml`（实测会出现，不拍就漏一份）。开跑前一份，
之后每成功一步再拍一份 —— 这样"退到上一步之前"才有落点。

🔴 **诚实边界**：`node_modules` 里的实体文件**不在快照内**。`remove` 能摘掉依赖链接，
但清不干净包管理器的缓存与虚拟store，所以回滚后可能还留着实体文件 —— 报告会明写这一句，
不会假装"回滚 = 什么都没变"。

## 清单（`suite-manifest.json`）= 单一真相

安装器读它；将来 `dsh-butler-core` 的装后自检也读**同一份**。任何一方想加判据，只能改这份清单
—— 两处真相必然漂移。

字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | ✅ | 包名（`@scope/name` 或裸名） |
| `versionRange` | ✅ | **期望区间**，写法只接受 `^x.y.z` / `~x.y.z` / `x.y.z`。不支持 `>=1.2`、`1.x`、`||` 组合 —— 与其两处语义各猜一半，不如让写法收敛 |
| `type` | ✅ | `plugin`（要进组合列表）/ `cli`（不参与挂载） |
| `group` | ✅ | 组名，`--only` 按组选 |
| `mount` | 插件可选 | `auto`（默认，装完应自动挂）/ `manual`（按设计不进组合列表，挂载由它自带的部署命令完成）/ `none` |
| `probe` | ✅ | 见下「探针」 |
| `aliases` | 可选 | `--only` 用的别名（如 `面板`、`看板`），不许与包名重复 |
| `note` | 可选 | 一句人话：这个包是什么、有什么坑 |
| `excluded[]` | 顶层可选 | **不可安装项**：不是包的目录（如历史聚合仓）。演练档会跳过它并打印原因 |

**期望版本一律写区间，不钉精确版本**：宿主落进 profile 的本来就是区间，
钉精确版本只会造出"清单与实体永远不一致"的假红。

## 探针（`probe.kind`）

| 值 | 干什么 | 什么时候能用 |
|---|---|---|
| `existence`（**默认**） | 只看文件在不在：插件看 `node_modules/<包>/package.json`，命令行看 `.bin` 或全局前缀下的命令文件。**一条命令都不执行** | 任何命令都能用 |
| `help` | 先**静态核**该命令源码里确有 `--help` 分支，再跑 `<命令> --help` | **仅当这条命令确实实现了 `--help`**。核不到就**拒绝执行**并判失败 |
| `cmd` | 跑清单指定的一个**只读**命令 | 清单里必须写 `readonlyBecause`：凭什么认定它只读 |

🔴 **为什么 `help` 要加硬闸**：这批命令行工具里有相当一部分没有参数解析，未知参数被忽略后
**直接执行真动作**（导出快照、归档、改状态）。拿 `--help` 当"只看一眼"是错的。
所以 `help` 探针在**执行之前**先读源码，找不到 `--help` 分支就拒跑 —— 宁可判红，不赌它是只读的。

要取证"哪些命令真的实现了 `--help`"，用随包附带的只读扫描器（一个命令都不跑）：

```powershell
npx -p @kira905/dsh-butler-install dsh-butler-install-probe-scan <某仓根或父目录>
```

只有它标 ✅ 的命令，才允许在清单里写 `probe.kind: "help"`。

## 常用参数

| 参数 | 说明 |
|---|---|
| `--profile <name>` | 必填。宿主会定位 `<数据根>/profiles/<name>` |
| `--apply` | 真装（不加就是演练档） |
| `--only` / `--skip` | 逗号分隔，认组名 / 包名 / 包名末段 / 别名 |
| `--upgrade` | 已满足的项也重跑一遍安装（"装过但坏了"的情形） |
| `--rollback[=step\|batch]` | 失败后怎么回滚，默认 `step` |
| `--uninstall` | 卸掉选中的包（不是回滚） |
| `--npm-prefix <dir>` | 全局包落点（默认取 npm 自己的全局前缀）。**隔离演练时用它**：装到临时目录，不碰你真正的全局包 |
| `--home <dir>` | DSH 数据根（默认 `$DSH_HOME`，再默认 `~/.dsh`） |
| `--timeout` / `--budget` | 单步超时（默认 120s）/ 整批墙钟上限（默认 300s，超了就停下并回滚本批） |
| `--snapshot-dir <dir>` | 快照目录，默认 `<数据根>/butler-install/snapshots/<时间戳>` |
| `--json` | 只输出一份 JSON 汇总（人读的输出改走 stderr） |
| `--ui` | 起一个**只读**的本地向导页（`127.0.0.1`、只有 `GET`、零执行），见上文。用它时 `--profile` 可省（默认 `web`） |
| `--port <n>` | 向导页端口（只在 `--ui` 时有用），默认 `45080`；被占用会自动换一个并打印实际地址 |

## 它在 Windows 上怎么跑子进程

`dsh` / `npm` 在这台机器上是 `.cmd` 壳：不带 shell 的 spawn 直接 `ENOENT`，
显式写 `.cmd` 又会 `EINVAL`。所以本工具在 Windows 上过 shell 执行，并且参数做了最小必要引号化
（只有含空格等特殊字符的参数才加引号）——打印出来的命令行与真正执行的命令行由同一个函数生成，
报告里不会出现"说要跑 A、实际跑了 B"。

## 已知限制（别当 bug）

- 回滚**不覆盖** `node_modules` 里的实体文件与包管理器缓存（见上文诚实边界）。
- 用 `--upgrade` 重装一个**之前就装着**的包、然后失败回滚时，声明层会回到快照值，
  但实体层可能变成"声明在、实体更新过"的中间态 —— 再跑一次安装即可对齐。
- `mount: "manual"` 的包（按设计不进组合列表、靠自带部署命令挂载）本工具只装不挂，
  挂载判据记"跳过"。
- 不判"运行时会不会崩"：`--dump-config` 只证明组合树里有这一行。真要验运行时，得自己起一次服务看日志。
- 不替你决定"要不要装某一件"，也不做"装完自动起服务"。
- 🔴 向导页**故意不能"点一下就装"**：那需要开一个能替你执行命令的写入口，风险面比省下的两次复制大得多。
  页面给的是命令，装的动作永远在终端里、由你按下回车。

## 夹具

```powershell
npm test
```

夹具全部落在自己的临时目录里（假 `dsh`、假 `npm`、假 profile、假全局前缀），
不读也不写真实数据根。覆盖：清单校验（每条错误都带文件名 + 行号）· 版本区间三态 ·
探针三分支（含"标了 `help` 但该命令没实现 ⇒ 拒执行且不产生任何执行"）· 组合树三条计数判据
（各自独立可触发）· 快照回放与核对 · 演练档零副作用（目录指纹必须一模一样）· 退出码 0/3/4 ·
步级与整批回滚的差别 · 卸载 · 向导页（监听地址只许 `127.0.0.1` / 除两个 `GET` 外全 405 / 页面数据与
`--dry-run` 同源 / 每请求零 spawn / 端口冲突自动换 / 不给 `--ui` 时输出逐字节不变）·
以及**变异测试**：把监听地址改成 `0.0.0.0`、或把路由表放开非 `GET`、或让命令字符串不带期望区间，
夹具必须**变红**（改坏了还绿 ⇒ 这条夹具是假的）。

### 清单漂移判据（`test/range-drift.mjs`）

清单是单一真相，但真相会烂：写清单那天按当天的 latest 填区间，之后某个包跨了 0.x 的小版本
（0 阶段里这就是大版本），caret 的上界就把新版挡在门外 —— 照清单装一遍拿到旧一套，而且装后自检
**照样绿**（它读同一份清单）。所以这条判据对着清单外面的世界核，而不是自己核自己：

```powershell
node test/range-drift.mjs                                    # npm view，真网络
node test/range-drift.mjs --offline test/fixtures/npm-latest-snapshot.json   # 读快照，零网络
node test/range-drift.mjs --json --manifest <别的清单>
```

退出码：`0` 全部接受 · `3` 有漂移（照清单装会拿到旧版）· `4` 取数失败/无法判定（**绝不当通过**）·
`2` 用法错或清单读不进来。`test/run-all.mjs` 里那一格走仓内快照、零网络；快照的 `capturedAt`
是这份数据"什么时候是真的"的凭据，刷新清单区间时记得一起刷。
